# `TK123` — public API review: what surprises a first-time user (the measured plan)

**ACTIVE-PLAN, opened 2026-10-14 — the body is provenance, not a living status.** This is
the execution map for `TK123`, produced by a seven-lens review sweep (six probing lenses,
one skeptical verifier per cluster) on 2026-10-14 and edited for taste by a final editor. Every
figure and line number below is as-of 2026-10-14. Live state is the task row (`python
scripts/task.py show TK123`), never this file. Corrections append **dated at the top**, never
edited into the body. Freeze it when `TK123` closes.

**Provenance key.** Every claim carries one of: **LENS PROBE** (a lens agent's probe, path
under `.scratch/tk123-review/probes/<lens>/`), **VERIFIER PROBE** (the skeptical verifier
re-ran it first-hand, path under `.scratch/tk123-review/probes/verify-N/`), **VERIFIER
READ** (verifier read the cited symbol), **EDITOR READ** (the editor grepped the cited
`file::symbol` and it resolves), or **REASONED** (nobody ran it). ⚠ `.scratch/` is
gitignored: the literal outputs that matter are transcribed into the evidence cells below,
because the probe files will not survive a sweep. The editor ran no probes; the editor's
first-hand work is the symbol-existence grep (every `file::symbol` cited here resolved in
`src/zanzibar/` on 2026-10-14) and the taste calls.

**Scope.** The decided rename (§2) is NOT re-litigated. What follows is what the rename
does not cover, what it would get wrong, and what else a first-time user of the published
`zanzibar-index` wheel trips over. One item was REFUTED outright (§ Appendix A); it is
dropped from the tables.

**Vocabulary for the per-item call.** **DO** = inside `TK123`, batched into the single API-
break release. **SPLIT** = a row of its own (named), because it is a feature, a semantic
decision, or owned elsewhere. **LEAVE** = not worth doing, with why.

## 1. Summary — the changes that most improve the first hour, ranked

1. **Make `import zanzibar` useful, lazily** (A14, A17, A18, A20): a PEP 562 `__getattr__`
   re-exporting `Store`, `LookupResult` (the graph class), `parse_openfga_schema` and *all
   eighteen* exception classes including the never-exported `WriteLockUnsafe`, without
   making `import zanzibar.schema` pay ~3 s for SQLAlchemy. Decided; not yet built.
2. **Make the README's own parameter names bind** (A4, A5): `subject_type` / `subject_name`
   / `object_type` / `object_name` / `subject_relation` on every public method, with a test
   that the documented names bind as keywords. Today `add_tuple(subject_type=...)` is a
   `TypeError`.
3. **Stop committing and discarding the caller's transaction** (A54): `Store.__init__`,
   `_write` and `refresh()` commit or roll back whatever the app had pending. Reuse the
   existing `build.py::_require_clean_session` refusal, and say "give the store its own
   Session" on the PyPI page.
4. **Let a `Store` user read a lookup without SQL on an internal table** (A21):
   `Store.result_keys` / `excluded_keys`, so the quickstart stops importing
   `zanzibar.graphindex.Node`.
5. **Close the public-name equivalence hole** (A16): `advance_index(proc=None)` on a boolean
   schema silently builds a graph index that disagrees with the set engine. Refuse it, and take
   `advance_index` / `ensure_cursor` off the public surface.
6. **The first error a user meets should be a library error with a hint** (A27):
   `StoreNotFound(KeyError)` saying `pass schema=...`, and roll back before raising so the
   SQLite write lock is released.
7. **Docstrings on the headline methods, and stop help() lying** (A37, A39, A42): `check` /
   `add_tuple` / `remove_tuple` / `watermark` have none; `help(zanzibar.setengine)` says the
   graph index cannot do `but not`, which the quickstart does.
8. **Tell async users how the index advances, and that untokened reads are stale** (A56,
   A57): a README async section with the caller-scheduled `catch_up()` loop; the intro's
   "falls back to the set engine" applies only to `at_least`-tokened `check`; a stale ALLOW
   after a revoke is possible until `catch_up()`.
9. **Strip repo-internal ids and paths from everything the wheel shows** (A29, A30, A38,
   A45): 11 runtime message sites and 64 of 145 public docstrings cite `TK`/`ZT`/`ASK` ids,
   `docs/`, `tests/` or `formal/`; the fanout/lock recipes point at files not in the wheel.
   One warning fires twice per `Store`. A permanent grep test, limited to the public surface.
10. **One `LookupResult` name, one meaning** (A2): rename the set-engine twin to
    `SetLookupResult` (a dataclass with `__eq__`); export only the graph class at top level.

Not in the top ten but the single largest decision: **A3**, the six-positional-strings
argument order `(pred, type, name, relation, type, name)` that matches neither OpenFGA nor
the library's own outputs. It is the one API break big enough to need the user's word (§5).

**What the review shows the rename table gets wrong or leaves dangling**

- **A1 (VERIFIER PROBE verify-0/p1_all.out).** After the move the class lives at
  `zanzibar.store.store.Store`: a module named like its package, in every traceback and repr.
  Rename the inner module in the same commit (`_store.py` or `core.py`). The "table
  `zanzibar_store` will mislead a DB browser" half is mostly refuted: the row id equals the
  `Store`'s id (`select id, description from zanzibar_store` → `[('app','')]`), so "one row
  per store" is broadly right. A docstring on `IndexStore` closes it.
- **A45 (VERIFIER PROBE verify-4/p09_rename_literals.py, an AST walk over shipped strings).**
  40 docstring, 9 message and 2 other string occurrences of `ConnectedStore` /
  `connectedstore` in `src/`; message sites `store.py:169-176` (`UnloggedTuplesPresent`),
  `setengine/engine.py:87-93` (`UnloggedWriteRefused`), `schema/boolean.py:714`
  (`CyclicDerivedDependency`), `graphindex/core.py:265`, `store.py:452`. PYPI_README 10 hits,
  README 7, `formal/CORRESPONDENCE.md` 16 `connectedstore/` anchors,
  `correspondence_anchor_pin.txt` 8. The top-level docstring "Deliberately imports nothing"
  becomes false. **Add to the rename checklist**: a permanent test that no shipped string
  constant names the old module or class (leave `CHANGELOG.md` history alone), and re-measure
  `import zanzibar` time after the change (REASONED).
- **A20 (VERIFIER PROBE verify-1/v6_import_cost.py).** Fresh-interpreter medians: `import
  zanzibar` 2.2 ms, `import zanzibar.schema` 361.5 ms (heavy deps `[]`), `import
  zanzibar.connectedstore` 3782.9 ms (`sqlmodel, sqlalchemy, pydantic, pyroaring`). An eager
  re-export makes every schema-only user pay the 3.8 s, and makes `import zanzibar.setengine`
  register the connected-store tables, which stales
  `docs/tk140-one-write-path-per-store-2026-10-13.md:67-70` (VERIFIER READ). Behaviour stays
  correct (`setengine/engine.py::store_has_schema_record` has a `has_table` check), but the
  doc line and the design intent both say lazy. Guard it with a test that `sqlmodel` is not in
  `sys.modules` after `import zanzibar.schema`, sabotaged once by making the import eager.
- **Anchors that move (VERIFIER READ).** `formal/CORRESPONDENCE.md` lines 454/457/1050/1073
  cite `src/zanzibar/connectedstore/store.py::ConnectedStore.catch_up`;
  `tests/test_claim_rot_gate.py:55,62` and `scripts/installed_smoke.py:247,346` name
  `connectedstore`. `verify.sh lean` (anchor check + claim-rot pin) is red until the 16
  anchors and 8 pin entries are updated and `claim_rot.py --generate` is re-run — the `TK120`
  precedent.

## 4. Implementation order, and what goes into the single API-break release

Everything marked DO lands in ONE release (`TK120` precedent: one CHANGELOG entry, no
shims). Current version is `0.0.4` (`src/zanzibar/__init__.py::__version__`, EDITOR READ);
the breaking release number is the user's call (§5 Q3). Order chosen so that every step
leaves the gate runnable and so that no docstring is written twice.

**Step 0 — re-measure the census (SCOUTING).** File count for `connectedstore` →
`store`, `Store` → `IndexStore`, the 16 CORRESPONDENCE anchors, the 8 pin entries, the
claim-rot content pin, the 277 `widx`/`proc`/`ensure_cursor` test sites. Record it in this
doc (dated correction at the top) before the first edit. The 2026-10-07 figure (~145 files)
is stale by definition.

**Step 1 — the mechanical rename (A1, A45, A14, A20, A17, A18).** Package and class rename
including the inner module; `IndexStore` with its docstring; lazy top-level `__getattr__` +
`__all__` + `TYPE_CHECKING` block; export all exceptions incl. `WriteLockUnsafe`; delete
`__all_exceptions__`; repoint anchors, regenerate the pin; "Renamed in TK123" key in
`docs/architecture/overview.md`; two new permanent tests (no old names in shipped strings;
`sqlmodel` absent after `import zanzibar.schema`), each sabotaged once. Gate green, commit.

**Step 2 — the surface trim (A15, A11, A12, A13, A9, A16, A7, A59).** Trim all four
`__all__` lists (keep import lines); drop `advance_index` / `ensure_cursor` / `open_*`;
`advance_index` guard with its sabotage test; `index_store_id` keyword-only; re-export
`prune_outbox` / `outbox_watermark`; `SetOps.__repr__`. Gate green, commit.

**Step 3 — the breaking signature changes (A4, A5, A2, [A3 if approved]).** Keyword
renames everywhere public, with the README-names-bind test; `SetLookupResult`; if the user
approves A3, the positional reorder — it touches the same call sites as A4, so doing them in
separate commits means touching every site twice. Both README quickstarts, `tests/parity.py`,
`formal/conformance/backends.py`, `scripts/installed_smoke.py` move with it. Gate green
(+ fuzz sweep: `parity.py` is in the matrix), commit.

**Step 4 — exceptions and refusals (A19, A27, A25, A34, A35, A50, A53, A54, A31, A32,
A36, A28).** `ZanzibarError` root + `SchemaError`; `StoreNotFound` + rollback; `IndexExists`;

## 5. Open questions for the user (goals and priorities only)

1. **A3 — is one hard positional break acceptable in this release?** Today the input order
   is `(subject_relation, subject_type, subject_name, relation, object_type, object_name)`
   and every output key is `(type, name, relation)`. The editor recommends the reorder to
   `(type, name, relation, ...)` now, because a second positional break later costs more and
   this release already breaks keyword names and the module path. The alternative is
   additive: accept `'user:alice'` / `'group:eng#member'` strings. Which?
2. **A19 — may `except ZanzibarError` catch corruption?** The editor recommends keeping
   `InvariantViolation` OUT of the root, so a broad catch never hides a corrupted index. Any
   objection to that priority (availability vs. loud corruption)?
3. **Release number.** `0.1.0` for the API break, or stay on `0.0.x`?
4. **A36 — should `Store(schema=<dict or JSON text>)` just work?** Dispatching to the JSON
   front end is the friendlier choice for OpenFGA users who hold the JSON model; a hint is
   the conservative one. (Mechanics are decided here; the question is only whether JSON
   users are a priority audience.)
