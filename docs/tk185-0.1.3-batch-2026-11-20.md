## Step 4 -- the design (DEC-16, PROVISIONAL) and the census it rests on

The design is [`DEC-16`](decisions/DEC-16-tk-185-step-4-reads-refuse-an-undeclared-type.md)
(PROVISIONAL, actor agent claude-opus-5-5): a new `UndeclaredTypeOrRelation(ZanzibarError,
ValueError)`; one shared schema-layer validator called at the top of the public `Store` reads
BEFORE token validation / freshness / dispatch, and at the top level of the `SetEngine` reads,
both on the SET ENGINE's `DeclaredRelations`, so the two refuse identically and the
`Store.check` fallback cannot change the outcome; `WildcardIndex` stays lenient (study surface,
Lean-modelled, content-pinned); the C5 result-key hint; no Lean model change (REASONED).

Census of the read surface (AGENT C, `.scratch/tk185/C-census.md` section A only -- the agent
stopped before sections B-F; the trap census is done EMPIRICALLY instead, by running the suite
against the change, step 4 below). Its load-bearing claims, as reported (AGENT, lines dated
2026-11-20):

- Public reads: `src/zanzibar/store/_store.py::Store.check` / `lookup` / `lookup_reverse` /
  `expand`; `src/zanzibar/store/source.py::TupleSource.check` (-> `SetEngine.check`);
  `src/zanzibar/setengine/engine.py::SetEngine.check` / `lookup` / `lookup_reverse` / `expand`
  (top level when `memo is None`) / `filter_result`; `WildcardIndex.check` / `lookup` /
  `lookup_reverse` / `filter_result` (public via `zanzibar.graphindex.__all__`, documented as a
  study surface in `userdocs/how-to/backends-direct.md`). No batch reads; `at_least=` only.
- Store dispatch: `check` -> graph when fresh, else set engine (stalled untokened, or tokened
  lagging); `lookup*` -> `_require_index_freshness` then graph, no fallback; `expand` -> always
  the set engine.
- Schema at hand: `SetEngine.ast` + `SetEngine._declared_types` (lazy `_declared`, built on the
  first write refusal); `Store` reaches it through `self.source.engine`; `WildcardIndex` holds no
  declared-types set.
- Leaf predicates `<relation>.<index>` are never declared, so they are refused at Store /
  SetEngine; internal leaf reads go through `WildcardIndex._check_internal`, below the fence.
- Content pins that move with a call inside the body (`formal/correspondence_anchor_pin.txt`):
  `SetEngine.check`, `SetEngine.expand`, `SetEngine.lookup_reverse` (and the three
  `WildcardIndex` reads, untouched under DEC-16 sec 5).
